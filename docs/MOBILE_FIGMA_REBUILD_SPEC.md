## 3. 화면별 변경사항 (Figma 원본 대비)

### 3.1 상단 GNB 헤더

- **원본(Figma)**: 하나로 이어진 단일 글래스 바.
- **변경**: 로고/타이틀, `💻 PC 뷰`, `🔍 검색`, `🔔 알림` 4개를 **각자 독립된 글래스 조각**으로 분리. 조각 사이 간격은 완전 투명 — 헤더 컨테이너 자체는 배경이 없다.
- **레이아웃**: 화면 상단에 `absolute`로 고정된 오버레이(뒤로 콘텐츠가 실제로 스크롤되어 지나간다 — 원본 sticky 구현은 스크롤 컨테이너가 없어 실질적으로 무효했던 버그였음). 좌우 패딩 16px(`px-4`), 상하 14px(`py-3.5`) + safe-area.
- 로고 조각: `glass-cta`, 내부 gap 10px, 아이콘 패딩 8px/12px, 반경 16px(`rounded-2xl`). 36×36px 네이비(`#002454`) 정사각 배지에 흰 "Y", 우측에 "연세 미디어센터"(14px black) / "SNS 기자단 모바일"(10px slate-500 semibold) 2줄.
- PC 뷰 / 검색 / 알림: 전부 `glass-cta`. PC 뷰는 pill(반경 16px) + 12px extrabold 텍스트, 검색·알림은 36×36px 원형.

### 3.2 대시보드

- 상단 카드형 대시보드(승인대기, 캐러셀 등)는 유지, 상세보기 진입은 모두 **peek 상태**로 열림(즉시 전체화면 아님) — peek 시작 위치는 화면 높이의 **69.2%**(Figma 실측치).
- peek 미리보기 콘텐츠 위에서 **좌우 스와이프**로 기획안⇄완성본 전환 가능(우측 스와이프→기획안, 좌측→완성본 — 최초 스펙과 반대 방향으로 최종 확정, §3.5 참고).
- 하단 액션바(기획안 작성/완성본 업로드)는 전체 리스트와 완전히 통합된 하나의 컴포넌트로 셸 레벨에 고정(§3.4 하단 액션바 참고).

### 3.3 캘린더

**그리드 뷰**
- 원본처럼 흰 카드(`bg-white rounded-3xl shadow`) 위에 얹힌 게 아니라 **셸 배경 위에 직접** 구성(첨부된 Timeblocks 참고 요청 반영).
- 셀: `min-height 88px`(`5.5rem`), 반경 8px, gap 4px.
- 날짜 숫자: 셀 좌상단의 20×20px 원형 배지(11px black, Inter 폰트). 선택된 날짜는 네이비(`#002454`) 채움 + 흰 텍스트, 셀 전체는 `bg-blue-50/90` + 2px 파란 링.
- 이벤트: 정사각 축소 뱃지가 아니라 **꽉 찬 너비의 막대(pill)**를 최대 3개까지 세로로 쌓고, 초과분은 "+N개" 텍스트(8px slate-400). 막대 색은 기획안(`#FFB800`)/완성본(`#00A859`) 그대로, 텍스트 8.5px bold.

**리스트 뷰**
- 날짜 배지: 기존엔 "일정" 라벨 + "{day}일" 2줄 구성이었던 것을 **숫자만** 44×44px 흰 박스(16px black bold)로 단순화.
- 정렬: 등록 순서가 아니라 **날짜 오름차순**(`target_date` 기준 `localeCompare` 정렬)으로 확정.
- 기획안/완성본 텍스트 뱃지 제거, 완성본이면서 Drive 링크가 있을 때만 32×32px Drive 아이콘 표시(전체 리스트와 동일 패턴).

### 3.4 전체 리스트

- 검색창 + 분기(2개월 단위) 필터 + 소속/유형 칩은 **기본적으로 숨김**, GNB의 🔍를 눌러야 펼쳐진다(`max-height` 트랜지션으로 접힘, 펼침 시 검색창 자동 포커스).
- 분기 필터 아이콘(📅): 44×44px, 활성 시 네이비 채움 + 우상단에 `#FFB800` 도트.
- **항목 선택 상태(신규 확정)**:
  - 기본: `bg-white`, `border-slate-200/80`
  - 선택됨: **배경 `#EAF2FF`(연한 파랑)**, **테두리 `#002454`(네이비) + 2px 링(20% 알파)**, **제목 텍스트도 `#002454`**(기존엔 검정 계열 `slate-900`이었음). 부제(작성자·팀)는 원래도 회색이라 변경 없음.
  - 탭하면 토글(다시 탭하면 선택 해제). 선택 해제 시 하단 액션바는 대시보드와 동일한 "기획안 작성/완성본 업로드" 버튼으로 자동 전환.
- 기획안/완성본 텍스트 뱃지 제거, 완성본+Drive 링크 있을 때만 32×32px Drive 아이콘.

**하단 액션바 (전체 리스트에서 항목 선택 시 — 대시보드/미선택 시와 공유하는 동일 컴포넌트가 조건부로 바뀜)**

| 상태 | 버튼 |
|---|---|
| 미선택 (대시보드 탭 / 리스트 탭 선택 없음) | `✍️ 기획안 작성`(`glass-cta`+`glass-cta-strong`, 네이비 텍스트, **font-weight 400**) · `📤 완성본 업로드`(`glass-cta-primary`, 흰 텍스트, **font-weight 400**) — 둘 다 56px(`h-14`) 고정 높이, 아이콘 텍스트 볼드 없는 버전으로 최종 확정 |
| 항목 선택됨 | `📋`(`glass-cta-kraft`, amber) 기획안 상세보기 · Drive 아이콘(조건부, 아래 참고) 완성본 상세보기 |

**Drive 아이콘 버튼의 조건부 노출 (신규 확정 — 권한 게이팅)**

```

완성본이 아직 없음

  → 그 외 단순 열람자면: 버튼 자체를 렌더링하지 않음(숨김)

```

### 3.5 상세보기 (기획안/완성본 공통 — 가장 크게 재구성된 화면)

- **원본(Figma)**: navy 헤더(기획안/완성본 전환 버튼 + 작성자 + X 닫기 버튼) + 흰 콘텐츠 + 하단 "닫기" 단일 버튼.
- **변경 후 구조**: 헤더 바 자체를 완전히 제거. 대신:
  1. **드래그 핸들**: 상단 중앙, 40×6px 회색 필(네이비 배경 없이 셸과 같은 톤).
  2. **좌상단 플로팅 상태 배지** (`absolute top-3 left-3.5`): "기획안 📝"(amber) / "완성본 🎬"(green), 12px black 텍스트, pill 형태. **탭 가능** — 아래 전환 로직 참고.
  3. **우상단 플로팅 작성자/날짜 칩** (`absolute top-3 right-3.5`, `glass-cta`): 11px bold, 작성자명 + 날짜 2줄, 우측 정렬. **제목 카드 밖**에 독립적으로 위치(카드 안이 아님 — 명시적으로 정정된 사항).
  4. 본문 콘텐츠는 흰 카드(`bg-white rounded-2xl border shadow-xs`)들의 세로 스택, 상단 여백 56px(`pt-14`)로 배지/칩과 겹치지 않게.
  5. **하단 액션**: "닫기" 단일 버튼 → **"✏️ 수정하기"(`glass-cta`+`glass-cta-strong`, 네이비) / "닫기"(`glass-cta-primary`, 흰색)** 2버튼. 두 버튼을 감싸던 배경 레이어(도크)는 제거해 콘텐츠 위에 버튼만 직접 떠 있음(헤더 해체와 같은 원칙).

**배지 탭 전환 로직**

```
현재 완성본 화면 → 탭하면 무조건 기획안으로 전환

현재 기획안 화면 → 탭했을 때:
  완성본이 이미 있으면 → 완성본으로 전환
  완성본이 없고, 내가 작성자면 → 완성본 업로드 화면으로 이동(onEdit)
  완성본이 없고, 내가 작성자가 아니면 → 전환하지 않고 화면 정중앙에
    검은 배경/흰 글씨 토스트 "아직 완성본이 업로드 되지 않았습니다" (1.8초 후 자동 소멸)
```

**좌우 스와이프 전환**: 본문 콘텐츠 위에서 좌우 스와이프하면 배지 탭과 동일하게 기획안⇄완성본 전환(우측 스와이프→기획안, 좌측→완성본). peek·전체화면 두 상태 모두에서 동작.

**peek/전체화면 상태**
- peek 시작 위치는 화면마다 다름: 대시보드 진입 69.2%, 캘린더 날짜팝업 진입 36.4%. 그 외(리스트/캘린더 리스트뷰) 진입은 즉시 전체화면.
- 닫기 동작: peek→전체화면으로 확장된 상태에서 닫기(뒤 배경 탭/닫기 버튼/아래로 스와이프)는 **한 번에 닫히지 않고 peek 상태로 한 단계만 복귀**, peek 상태에서 다시 닫아야 완전히 사라짐.

**리치 텍스트 정규화**: 기획 의도/구성 및 내용/촬영 계획/비고 등 리치 텍스트 필드는 원본이 어떤 폰트·크기·색으로 입력·붙여넣기 되었든 항상 카드 기본 서식(12px slate-700)으로 강제 통일. 볼드/이탤릭만 최소한으로 살아있고, 리스트(불릿)는 들여쓰기가 카드 밖으로 나가지 않도록 패딩 확보.

## 5. Figma 프로토타입만으로는 표현이 어려운 로직 (참고 메모)

- **권한 기반 조건부 렌더링**(관리자/작성자 여부에 따라 Drive 버튼 노출 여부가 달라지는 것)은 실제 로그인 세션을 참조하는 로직이라 Figma 프로토타입의 정적 조건부 분기로는 완전히 재현되지 않는다. Variables/조건부 컴포넌트로 "관리자로 보기" / "작성자로 보기" / "타인으로 보기" 3가지 프리셋 프레임을 만들어두고 설명을 남기는 방식을 권장.
- **리치 텍스트 서식 강제 통일**은 런타임에 임의의 붙여넣기 HTML을 규칙으로 눌러버리는 동작이라, Figma에서는 "항상 이 서식으로 보임"이라는 결과 상태만 표현 가능.
- `backdrop-filter` 블러의 정확한 강도는 브라우저 렌더링에 따라 미묘하게 달라질 수 있어, Figma의 Background blur 값(10px)은 근사치로 취급.
